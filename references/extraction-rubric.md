# 提炼规则与引用

## 收什么

可迁移的判断规则、适用前提、机制解释、可实际核验的判据。具体案例可以帮助解释，但不能把单次经验升格为普遍规律。对短视频不设置要点数量下限。

不把行情播报、情绪安慰、推广话术、纯新闻转述当成方法论。研究商业模式时，作者的推广/收入自述可能是相关证据，但仍需标记为自述。

## 不改作者的意思

原文“走强”如果没有定义，就保留其模糊性。不能擅自变成“站上某条均线”或添加数字阈值。研究者提出的操作化解释要单独标为推测，不作为作者规则。

不要把某个创作者的估值、技术指标或策略包装成普遍有效的投资建议。保留语境、对象、时间与例外。

## 要点格式

```markdown
## 方法论要点
### 用小范围观察检验流程
- **先用少量材料检查流程是否可执行，再扩大处理范围。** 这是作者在本例提出的流程规则。 [00:00:00]
```

时间戳必须在该文件的逐字稿正文中已有锚点；另记原视频链接。全文没有规则时写明“本期未提取到可复用规则”，保留被处理过的记录，不捏造要点。

## 多视频总纲

总纲至少包括适用前提、分类规则、观点变化/一致性检查、使用限制和素材清单。首选 `[video:VIDEO_ID]`；遗留日期索引 `[YYYYMMDD]` 仅用于同日唯一视频。

合并同一规则时保留全部支持索引，不能凭出现频次判断规则正确。对矛盾先比较前提、时间、对象及定义；视频内的观点变化不一定是矛盾。

有数字的主张另记台账：主张、条件、视频 ID、时间戳、外部验证需求、当前状态。没有独立证据，不宣称预测已被证伪。作者自述收益不是审计数据。

检查程序证明文件/时间戳存在，不证明转录准确或语义支持；Agent 和使用者仍应复核关键结论。
